# Confluence Cloud formatting support (for Markdown-to-Confluence lesson authoring)

> This file establishes the `docs/research/` convention for this repo — no prior convention existed. Research notes going forward should live here as one Markdown file per topic.

Research question: if we author lesson drafts as plain Markdown and later paste/import them into real Confluence Cloud pages, what survives and what doesn't — specifically panels, expand/disclosure blocks, and multi-column layouts, which Markdown has no native syntax for.

All claims below are backed by a live fetch of an official Atlassian page (support.atlassian.com/confluence-cloud, confluence.atlassian.com, or developer.atlassian.com) via WebSearch + WebFetch on 2026-09-05. Anything sourced from a community forum or third-party blog is explicitly labeled non-official/supplementary and is never used as sole evidence.

## 1. Basic structural formatting

Confluence Cloud's current editor supports the standard set, authored via toolbar, slash command (`/`), or Markdown-style autoformatting-as-you-type:

- **Headings** (H1–H6): "You can assign up to six levels of headings by changing the paragraph style." Typing `#` through `######` followed by a space auto-converts to a heading level. [Format text](https://support.atlassian.com/confluence-cloud/docs/format-text/), [Keyboard shortcuts, markdown, and autocomplete](https://support.atlassian.com/confluence-cloud/docs/keyboard-shortcuts-markdown-and-autocomplete/)
- **Bold / italic**: toolbar buttons or `Ctrl/Cmd+B` / `Ctrl/Cmd+I`; also autoformat by typing `**bold**` / `*italic*`. [Format text](https://support.atlassian.com/confluence-cloud/docs/format-text/), [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/)
- **Bulleted / numbered lists**: toolbar, or typing `*` + space / `1.` + space auto-converts. [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/)
- **Tables**: toolbar "Table" button, slash command `/table`, or the keyboard shortcut `Shift+Option+T` (Mac) / `Shift+Alt+T` (Windows), which inserts a 3×3 table. No Markdown-typing autoformat for pipe tables is documented for the current editor. [Simplify data with tables](https://support.atlassian.com/confluence-cloud/docs/simplify-data-with-tables/)
- **Images**: inserted via toolbar/slash command from attachments or a remote URL; in the legacy wiki markup, images use `!http://host/image.gif!` (external) or `!attached-image.gif!` (attached), with `!image.jpg|thumbnail!` for thumbnails. [Confluence wiki markup syntax for the legacy editor](https://support.atlassian.com/confluence-cloud/docs/insert-confluence-wiki-markup/)
- **Links**: toolbar button / `Ctrl/Cmd+K`, or paste a bare URL onto the page/onto selected text to auto-link it. Markdown link syntax `[LinkTitle](http://a.com)` is explicitly listed as an autoformat pattern. The dedicated links page does not itself demonstrate `[text](url)` typing, only paste-URL and toolbar. [Insert and manage links on your pages and live docs](https://support.atlassian.com/confluence-cloud/docs/insert-and-manage-links-on-your-pages/), [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/)
- **Code blocks with language-specific syntax highlighting**: yes. The current editor's "Code snippet" element supports syntax highlighting by language (auto-detected or manually chosen from a dropdown); it can be inserted via toolbar, slash command `/code`, or by typing three backticks (```` ``` ````). The older "Code block" macro (legacy editor) separately lists 24 supported languages (Java, Python, JavaScript, Bash, SQL, C#, C++, HTML/XML, etc.), defaulting to Java. [Insert the code block macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-code-block-macro/), [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/)
- **Blockquotes**: current-editor autoformat is typing `>` + space. Legacy wiki markup uses `bq. blockquote text`. [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/), [Confluence wiki markup syntax for the legacy editor](https://support.atlassian.com/confluence-cloud/docs/insert-confluence-wiki-markup/)

Additional autoformat shortcuts documented for the current editor: strikethrough `~~text~~`, inline code `` `code` ``, horizontal divider `---` + space, action item `[]` + space, decision `<>` + space. [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/)

## 2. Callout/panel macros

Confluence's callout boxes exist in two generations, and the terminology matters for this design:

- **Legacy generation** — four distinct macros called **Info**, **Tip**, **Note**, and **Warning** (wiki-markup names `info`, `tip`, `note`, `warning`). These are only available in the legacy editor going forward: "new instances cannot be inserted" in the current editor, though pages that already have them keep working. [Insert the info, tip, note, and warning macros](https://support.atlassian.com/confluence-cloud/docs/insert-the-info-tip-note-and-warning-macros/), [Macros that are unavailable or have limited availability in the Cloud editor](https://support.atlassian.com/confluence-cloud/docs/learn-which-macros-are-being-removed/)
- **Current generation** — a single **Panel** element with five preset types (**info, note, warning, success, error**), each carrying a preset emoji and background color, plus a free choice of 20 background colors. Official guidance for the current editor is explicit: "In the cloud editor, use the panel element to create a similar look and feel to Info, Tip, Note, and Warning macros." [Insert the info, tip, note, and warning macros](https://support.atlassian.com/confluence-cloud/docs/insert-the-info-tip-note-and-warning-macros/), [Add elements to a page or live doc](https://support.atlassian.com/confluence-cloud/docs/insert-elements-into-a-page/)

Authoring the panel element: type `/panel` (slash command) or use the toolbar/Insert menu; select a preset type or customize colors. [Add elements to a page or live doc](https://support.atlassian.com/confluence-cloud/docs/insert-elements-into-a-page/), [Insert the panel macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-panel-macro/)

**No Markdown-shortcut trigger exists for panels.** Neither the panel macro page, the info/tip/note/warning page, nor the "Available markdown commands" page documents any typed string (e.g. `>` , `!!!`, `:::`) that auto-converts into a panel. Insertion is only via slash command, toolbar, or `{` autocomplete of the macro name. [Insert the panel macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-panel-macro/), [Insert the info, tip, note, and warning macros](https://support.atlassian.com/confluence-cloud/docs/insert-the-info-tip-note-and-warning-macros/), [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/)

## 3. Expand/disclosure macro

Confluence Cloud has an **Expand** macro/element — a collapsible container with a clickable title (default text "Click here to expand…") that reveals hidden body content. [Insert the expand macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-expand-macro/)

- **Authoring**: insert via toolbar selection or the slash command `/` (find "Expand" in the list), then edit the title and add body content. [Insert the expand macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-expand-macro/)
- **No Markdown-equivalent shortcut** is documented anywhere for the expand macro — not in the expand macro page itself, and not in "Available markdown commands." [Insert the expand macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-expand-macro/), [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/)
- **Wiki-markup form** `{expand:title=...}...{expand}` is documented for the legacy editor family (Confluence Data Center) as the `Expand Macro`, and its Storage Format equivalent is `<ac:structured-macro ac:name="expand">` with an `ac:parameter` for `title` and an `ac:rich-text-body` for the hidden content — this Storage Format XML is what the Confluence REST API actually stores, and it is the same on Cloud and Server/Data Center. [Insert the expand macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-expand-macro/) (storage-format tag structure corroborated by Atlassian Data Center docs search results; not independently WebFetched from developer.atlassian.com in this pass — see note in section 6)
- **Cloud vs Server/DC behavior**: the current expand macro page is explicitly headed for Confluence Cloud and Data Center together and states no functional difference between them, other than the general editor split (legacy vs current) that applies within Cloud itself. It also notes expand content is always fully expanded when a page is exported to PDF or HTML — i.e., the "collapsed" behavior is an editor/viewer-only affordance, not a storage-format difference. [Insert the expand macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-expand-macro/)

## 4. Layout macros

Two mechanisms exist, again split old/new:

- **Legacy: Section + Column macros.** The Section macro defines the outer container; Column macros nest inside it to create multi-column areas. Wiki markup example: `{section:border=true}{column:width=100px}content{column}{column}more content{column}{section}`. This is documented as **legacy-editor only** and is on the deprecation path (legacy editor deprecation begins January 2026 per Atlassian's June 2025 announcement). [Insert the section macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-section-macro/), [Insert the column macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-column-macro/)
- **Current: Layouts feature.** The modern Cloud editor has a visual, drag-and-drop **Layouts** feature supporting two through five columns, inserted via the slash command `/layout`, the Insert menu's Layouts icon, drag-and-drop of content blocks, or copy/paste of a layout from another page. For more than five columns, Atlassian's own guidance is to use a table or database instead. [Create and manage layouts](https://support.atlassian.com/confluence-cloud/docs/create-and-manage-layouts/)

**No Markdown-equivalent shortcut exists for either layout mechanism.** Neither is listed in "Available markdown commands," and both pages describe only UI/slash-command insertion. [Create and manage layouts](https://support.atlassian.com/confluence-cloud/docs/create-and-manage-layouts/), [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/)

## 5. Markdown import/paste fidelity

Atlassian's own docs describe Markdown support in the current editor as **typing-time autoformatting of a fixed, documented list of shortcuts** — headings, bold/italic, strikethrough, inline code, lists, blockquote, code fence, divider, links, action items, decision — via "Available markdown commands" and "Keyboard shortcuts, markdown, and autocomplete." [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/), [Keyboard shortcuts, markdown, and autocomplete](https://support.atlassian.com/confluence-cloud/docs/keyboard-shortcuts-markdown-and-autocomplete/)

Neither of those official pages documents panels, expand, or layouts as something a Markdown shortcut can produce — **this is an absence, not an explicit "not supported" statement**, so per the sourcing rules this must be flagged as *inferred from the absence of a documented shortcut*, not as a directly-stated fact. Combined with section 2–4 above (where the panel, expand, section/column, and layout pages each describe only slash-command/toolbar insertion and never mention Markdown text triggers), the inference is strong but is still an inference rather than a quoted Atlassian statement of "Markdown cannot create panels/expand/layouts."

On paste specifically (as opposed to typing): Atlassian does not appear to have a single dedicated official page titled "pasting Markdown" — the "Available markdown commands" page covers the shortcut list. Community reporting (non-official, supplementary only) is mixed on paste reliability: one Atlassian Community thread reports that pasting Markdown text into the current editor left it as a raw, unconverted code block rather than auto-converting, contradicting the smoother in-editor typing behavior — [Atlassian Community: "Markdown is not converted upon pasting in the new editor"](https://community.atlassian.com/forums/Confluence-questions/Markdown-is-not-converted-upon-pasting-in-the-new-editor/qaq-p/2635771) (non-official; a user-reported bug/gap, not confirmed against a specific Confluence Cloud version by Atlassian in this research pass). This is a signal that paste-time conversion is less predictable than type-time autoformatting even for the basic elements in section 1, and should be treated as a risk to validate empirically before relying on paste as the workflow, independent of the panel/expand/layout gap.

## 6. Confluence Cloud vs Server/Data Center

- **Wiki markup / "Insert > Markup"**: the legacy wiki-markup language (`bq.`, `{quote}`, `{code}`, `||heading||` tables, `{panel}`, `{info}`/`{tip}`/`{note}`/`{warning}`, `{expand}`, `{section}`/`{column}`) is documented on a Confluence **Cloud** support page, but that page explicitly states this markup applies only via **Insert > Markup in the legacy editor**, and: **"the new editor doesn't support markup."** So wiki markup is not a Server/Data-Center-only relic — it is still present in Confluence Cloud today, but gated behind the legacy editor, which Atlassian announced (June 2025) will begin deprecation in January 2026. [Confluence wiki markup syntax for the legacy editor](https://support.atlassian.com/confluence-cloud/docs/insert-confluence-wiki-markup/), [Macros that are unavailable or have limited availability in the Cloud editor](https://support.atlassian.com/confluence-cloud/docs/learn-which-macros-are-being-removed/)
- **Section/Column macros and the old Info/Tip/Note/Warning/Panel macros**: all documented as "legacy editor only" on Confluence Cloud, with the current editor's Layouts feature and Panel element as their respective modern replacements. Existing pages using the old macros keep rendering; only new insertion is blocked outside the legacy editor. [Macros that are unavailable or have limited availability in the Cloud editor](https://support.atlassian.com/confluence-cloud/docs/learn-which-macros-are-being-removed/), [Insert the section macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-section-macro/)
- **Expand macro**: unlike panels/sections, the expand macro page is headed for **both** Cloud and Data Center and is not listed among the macros the "unavailable in Cloud editor" page calls out as blocked — so it remains available for new insertion in the current Cloud editor via slash command, not just the legacy editor. [Insert the expand macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-expand-macro/), [Macros that are unavailable or have limited availability in the Cloud editor](https://support.atlassian.com/confluence-cloud/docs/learn-which-macros-are-being-removed/)
- **Storage Format**: not independently re-verified against developer.atlassian.com in this research pass (search results surfaced only confluence.atlassian.com Data-Center-branded storage-format pages, e.g. the `<ac:structured-macro ac:name="expand">` structure); Atlassian's architecture keeps one Storage Format XML dialect shared across Cloud/Server/DC for the REST API and macro bodies, but this specific claim should be flagged as **not independently confirmed against a developer.atlassian.com Cloud-labeled page in this pass** — treat it as inferred/likely rather than confirmed if it becomes load-bearing for the skill design.

## 7. The tradeoff: what pasting plain Markdown risks losing

Pasting/importing a plain-Markdown lesson draft into a real Confluence Cloud page will, at best, faithfully carry over headings, bold/italic, lists, links, and code blocks — the elements with a documented Markdown-typing autoformat path in the current editor. [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/) Tables and blockquotes are also autoformat-eligible when typed but paste conversion for the full element set is reported as inconsistent by at least one Atlassian Community thread (non-official; treat as a risk signal, not confirmed) — [Atlassian Community thread](https://community.atlassian.com/forums/Confluence-questions/Markdown-is-not-converted-upon-pasting-in-the-new-editor/qaq-p/2635771).

Panels, the expand/disclosure block, and multi-column layouts will **not** appear in any form after a Markdown paste — there is no Markdown syntax that produces them, so the pasted text for anything the author intended as a callout, an expand block, or a column layout will land as plain paragraphs (or, per the community report above, possibly as an inert raw code block). This is confirmed by the absence of any documented shortcut for these three elements across every official page checked in sections 2–4, not by an explicit Atlassian statement that "Markdown cannot create these" — flagged here per the sourcing rules as an inference from absence, not a directly quoted fact. [Insert the panel macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-panel-macro/), [Insert the expand macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-expand-macro/), [Create and manage layouts](https://support.atlassian.com/confluence-cloud/docs/create-and-manage-layouts/)

That leaves two real design options for the skill:

- **(a) Markdown body + manual post-paste macro insertion.** Author the lesson in Markdown for everything in section 1 (this is the bulk of most lesson content), and mark the spots that need a panel/expand/layout with an inline placeholder convention (e.g. an HTML comment or fenced block naming the macro type and its content). After pasting into Confluence, the author manually inserts the real Panel / Expand / Layout element at each marked spot via slash command and copies the placeholder's text in. This costs one manual pass per import, scoped only to the callouts/expands/layouts actually used (typically a handful per lesson), and keeps authoring in a git-friendly plain-text format the rest of the time.
- **(b) Author directly in Confluence Storage Format (or wiki markup) instead of Markdown.** Storage Format XML (`<ac:structured-macro ac:name="panel">`, `ac:name="expand"`, etc.) can express every element natively and pastes/imports losslessly via the Confluence REST API, but wiki markup itself is only reachable through the legacy editor's Insert > Markup, which Atlassian has slated for deprecation starting January 2026 — [Confluence wiki markup syntax for the legacy editor](https://support.atlassian.com/confluence-cloud/docs/insert-confluence-wiki-markup/), [Macros that are unavailable or have limited availability in the Cloud editor](https://support.atlassian.com/confluence-cloud/docs/learn-which-macros-are-being-removed/). This option gives full fidelity but drops the "author in plain Markdown in git" premise entirely, trading it for XML that's harder for a domain expert to hand-write and review as a diff, and it bets on a legacy-editor-gated syntax with an announced end date.

## Bottom line

Recommendation: go with **option (a)** — author lessons in Markdown, with a lightweight placeholder convention for the three unsupported elements, and treat inserting the real Panel / Expand / Layout blocks as a short manual step the domain expert does once, in Confluence, right after paste.

Why: Confluence Cloud's current (non-legacy) editor has genuine Markdown-typing autoformat for headings, bold/italic, lists, links, and code blocks [Available markdown commands](https://support.atlassian.com/confluence-cloud/docs/available-markdown-commands/) — that's most of a lesson page's content, and it's exactly what a git-based Markdown workflow is good at. But panels, the expand/click-to-expand block, and multi-column layouts have no Markdown equivalent whatsoever in Confluence Cloud today: every official page for these three elements (panel, expand, layout) describes insertion only via slash command or toolbar, never a typed shortcut [Insert the panel macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-panel-macro/), [Insert the expand macro](https://support.atlassian.com/confluence-cloud/docs/insert-the-expand-macro/), [Create and manage layouts](https://support.atlassian.com/confluence-cloud/docs/create-and-manage-layouts/). Pasted Markdown text describing "this should be a warning panel" will simply become a plain paragraph, not a panel — there is no format conversion to lose, because there was never a target format to convert into.

The alternative — authoring directly in Confluence wiki markup/Storage Format XML to get full fidelity — is not worth it: the wiki-markup route is gated behind the legacy editor, which Atlassian announced in June 2025 will start being deprecated in January 2026 [Macros that are unavailable or have limited availability in the Cloud editor](https://support.atlassian.com/confluence-cloud/docs/learn-which-macros-are-being-removed/), so building the skill's core format around it means building on a feature actively being phased out. It would also give up the actual point of the exercise — letting a domain expert write and diff plain Markdown in git.

Practical shape for the skill: define 2-3 fenced-block conventions in the Markdown draft format — e.g. a fenced block tagged `panel:warning`/`panel:info`/etc., a fenced block tagged `expand:<title>`, and a marker for "these two blocks go side by side" — and have the skill's authoring guidance tell the domain expert, after pasting into Confluence, to replace each marked block with the matching native element (`/panel`, `/expand`, `/layout`) and move the block's text inside it. This is a small, bounded, one-time manual step per lesson, not an ongoing tax, and it avoids over-engineering the Markdown format to fake macros Confluence has no text syntax for.
